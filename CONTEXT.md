# Thinktable — Architecture Context

Official product terms: **`DEFINITIONS.md`**.

## Product north star

Thinktable is a spatial mind-map on **boards** (see `DEFINITIONS.md`):

1. **Keeps first-class local content** — frames (boxes holding TipTap blocks), boards (titled frames with their own board), chat panels, flashcards, and drawings work without Notion (current behavior remains).
2. **Optionally connects Notion** — users OAuth-connect their workspace (Mindmap.so-style), pick Notion pages, map them on the board, edit on-site, and sync both ways.
3. **Exposes an MCP server** — external AIs (Cursor, Claude, etc.) can create/edit mind maps via tools, using the user’s Thinktable account (and optional Notion connection).

## Ownership split

| Concern | Source of truth |
|---|---|
| Board / frame **content** (when Notion-linked) | Notion (bidirectional sync via API) |
| Spatial **layout**, threads, board metadata | Thinktable |
| Local-only frames (no Notion link) | Thinktable only |

## Auth / Notion connect (MVP)

- Public Notion OAuth connection (`owner=user`).
- Capabilities: read + insert + update content; view workspace users (as needed).
- Redirect: `{SITE_URL}/api/notion/callback`.
- Tokens stored in `notion_connections` (service-role access only; not exposed to browser).
- Top bar **More** menu → **Connections** starts connect / shows connected state. After access + import, a **Notion mark** pins **left of Share**; click opens a **connection popup** (Import pages / **Edit permissions** / Unpin / Disconnect). **Edit permissions** is a native `<a href="/api/notion/auth?returnTo=…">` (full document navigation → 302 to Notion’s Select pages OAuth UI). Unpin hides the mark (`localStorage` `thinktable-notion-topbar-pinned`) without disconnecting.
- Notion Data API pinned to **`2025-09-03`** (`NOTION_VERSION`): databases are containers; schema + query use **`/v1/data_sources`**. Table load accepts a database id or data_source id (resolves `data_sources[]`, falls back to direct data_source retrieve). **Views API** (`lib/notion/views.ts`, Notion-Version `2026-03-11`): list/retrieve views for the embed’s `database_id`; **row set comes from `POST /v1/views/{id}/queries`** (Notion applies filter/sorts/`quick_filters` server-side — linked views often have `filter: null` with real chips in `quick_filters`), then properties are hydrated from the data source and ordered to match. Linked embeds (`empty data_sources`) never fall back to listing the source’s unfiltered “All” view or dumping the full DB. Return `notionView` to seed Thinktable layout when `viewSettings` is empty. **Empty `data_sources`**: resolve `data_source_id` from the view first, then URL source id, then fuzzy title search; if still unresolved, hide the table body (title/Notion chrome only) instead of a red error. Search normalizes `data_source` → `database` for the picker/import.
- After connect / **Import pages**: opens a Mindmap.so-style picker with Notion **tree** (nested pages), search, **Add frame** (Notion page or picked DB → title-variant `boardLink` frame like local board blocks + nested Thinktable board whose board-body holds the Notion content / `databaseBlock`; `notionPageId` / `notionUrl` for sync; same open menu as local boards + Notion icon right of open), and **Generate mindmap** (walks `child_page` + `child_database`; parent→child **threads**; Notion **pages** and **databases** → title-variant `boardLink` frames (DB name as title) + nested Thinktable boards; the nested board body holds the page content or live `databaseBlock` table via `/api/notion/database/[id]` — never one map frame per DB row; resolves `block_id` parents). **Add frame** on a nested DB inside a page body stays a compact `databaseBlock` (same table NodeView). Also creates nested Thinktable boards in the nav (linked via `linkedBoardId` / `sourceBlockMessageId`). **Sub-pages:** Notion `child_page` blocks become TipTap `boardLink`s in the parent board body; each sub-page gets its own Thinktable board with only that page’s content (discovered recursively on import even in card mode). Nested Notion **databases** inside a page body stay as TipTap `databaseBlock` atoms (table icon + title + Notion icon). Legacy sole-`databaseBlock` map frames for Notion **pages** migrate to `boardLink` on load via `ensureNotionMapFrameIsBoardLink` / `migrateSoleDatabaseBlockToBoardLink` (`lib/notion/migrate-frame.ts`) — including frames that never got `linkedBoardId`. Notion **`notionObject: database`** frames and board bodies **do not** auto-migrate (row→card remount used to rewrite the live table away); wiped empty DB bodies self-heal via `restoreWipedDatabaseBlockHtml`. Card-view frames (`dbLayout: 'card'` / property cells) are **not** repaired to a sole `boardLink` (that stripped the card on mount / drag). Empty TipTap saves never overwrite frames that still have boardLink/databaseBlock/property atoms. TipTap `useEditor` for frames uses a **non-empty deps array** so RF drag ticks don’t `setOptions` every frame (that remounted `databaseBlock` NodeViews and hugged the frame down to a Notion-icon stub). Live Notion table data is cached in React Query (`['notion-database', id]`, 5m staleTime) so any NodeView remount paints from cache instantly — no Notion reload spinner on drag. Frame drag **ignores TipTap onUpdate** (`suspendContentSync`, armed on pointerdown before RF `dragging`) and restores boardLink/propertyBlock HTML on drag-end so row cards don’t wipe to an empty I-bar; hug waits until property NodeViews remount (avoids first-drag collapse that a second drag “fixed”). Force-sync keys are not consumed while suspend is on. Unselected DB frames: table is **not** `nodrag` (only when the frame is selected) so grabbing the table moves the frame; `.tt-frame-unselected .tt-notion-db { pointer-events: none }` so cell `stopPropagation` doesn’t block drag. DB table cells are **editable** (title/text/number/checkbox/select/multi_select/status/url/email/phone/date) via `PATCH /api/notion/page/[id]` → Notion page properties; select menus list **all schema options** from the DB property (not only current cell values). DB **view settings** (Thinktable-owned, on `databaseBlock` `viewSettings` JSON): drag property order + hide/show, search, filters, multi-sort, group-by, conditional row colors, sub-tasks (relation nesting), layouts (**table / board / list / gallery / calendar** live; timeline/chart/feed/map stubs) + layout toggles — UI `database-view-settings.tsx`, transforms `lib/notion/database-view.ts`. DB **rows** (Notion pages) show a left ⋮⋮ handle (click selects the row + opens `BlockActionsMenu`; drag onto the board creates a **new Notion database** seeded with that row and drops a `databaseBlock` frame). **Convert layout → Card view** peels that row into a property card on the **same board** (client-side insert + thread to the DB frame; table stays). Nested/parent rows open a **Bring related rows?** dialog (**sub-rows** + **parent rows**, both default on; prefs in `localStorage` `thinktable-card-convert-bring-v3`). Brought frames share one **collapsed** `sideStacks` group (`sideStackGroupId(hostCardId,'bottom')`, same as Stack under): same position, host index 0 / `anchor` / `expanded:true`, mates `expanded:false` (hidden), group locked. Highest parent is the host (index 0 / top). Peeled rows are **hidden from the live table** (matched via board messages with `dbLayout: 'card'` + same `notionDatabaseId` / `notionPageId`) so the card is the only board for that row. (1px `#e5e7eb`, darkens on insert hover; CSS `group-hover/gutter`; no extra `tr` border — td rules only so alignment matches) (`POST /api/notion/database/[id]` create, `DELETE /api/notion/page/[id]` archive). Table chrome: no outer perimeter — TipTap `.prose table th/td` full-cell borders are wiped for `.tt-notion-db` in `globals.css`; only internal row rules + optional vertical dividers (`showVerticalLines`) remain. Row ⋮⋮ sits in wrap `paddingLeft` via absolute `-left` on the first cell — that cell must `overflow:visible` (inner wrapper clips text); table uses `border-separate`/`spacing:0` because `border-collapse` ignores cell overflow.

- Full Notion editor parity on day one.
- Replacing local notes with Notion-only.
- Marketplace listing / Notion security review (later for public distribution).

## Naming

Official terms live in **`DEFINITIONS.md`**. Short form:

| Official | Meaning | Code today |
|---|---|---|
| **Board** | The canvas (`/board/{id}`) | `conversations` |
| **Frame** | Box holding text (one or more **blocks**) | RF `chatPanel`, `metadata.isBlock` |
| **Block** | TipTap line + ⋮⋮ (not the box) | `EditorBlockRef`, `tiptap-block-handles` |
| **Thread** | Line between frames | RF `Edge`, `panel_edges` |
| **Connection point** | Knob that starts/receives a thread | RF `Handle` |

No “block group” type — multiple blocks in a frame is still a frame. RF `blockGroup` is legacy wrapper chrome. `metadata.isBlock` means **frame**, not TipTap block. Select **frame** before caret; ⋮⋮ drag = **block** only when armed via ⋮⋮ click, else **frame**. Frame **select** is click-release only (RF mousedown select blocked); mid-press hides connection indicators only — resize/⋮⋮/rotate stay mounted (`pressing` must not unmount `NodeResizeControl`). Unselected **move** shows a transient blue box and does not select; **already-selected** frame drag (body / chrome — not text, ⋮⋮, adjust handles, connection simulators, or property/connection marks) keeps the frame selected.
