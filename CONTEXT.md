# Thinktable — Architecture Context

Official product terms: **`DEFINITIONS.md`**.

## Product north star

Thinktable is a spatial mind-map on **boards** (see `DEFINITIONS.md`):

1. **Keeps first-class local content** — frames (boxes holding TipTap blocks), boards (titled frames with their own board), chat panels, flashcards, and drawings work without Notion (current behavior remains).
2. **Optionally connects Notion** — users OAuth-connect their workspace (Mindmap.so-style), pick Notion pages, map them on the board, edit on-site, and sync both ways.
3. **Exposes an MCP server** — external AIs (Cursor, Claude, etc.) can create/edit mind maps via tools, using the user’s Thinktable account (and optional Notion connection).

## Ownership split

| Concern | Source of truth |
|---|---|
| Board / frame **content** (when Notion-linked) | Notion (bidirectional sync via API) |
| Spatial **layout**, threads, board metadata | Thinktable |
| Local-only frames (no Notion link) | Thinktable only |

## Auth / Notion connect (MVP)

- Public Notion OAuth connection (`owner=user`).
- Capabilities: read + insert + update content; view workspace users (as needed).
- Redirect: `{SITE_URL}/api/notion/callback`.
- Tokens stored in `notion_connections` (service-role access only; not exposed to browser).
- Top bar **Notion** button starts connect / shows connected state (same OAuth UX Notion hosts — workspace picker → permissions → select pages).
- Notion Data API pinned to **`2025-09-03`** (`NOTION_VERSION`): databases are containers; schema + query use **`/v1/data_sources`**. Table load accepts a database id or data_source id (resolves `data_sources[]`, falls back to direct data_source retrieve). **Views API** (`lib/notion/views.ts`, Notion-Version `2026-03-11`): list/retrieve views for the embed’s `database_id`; **row set comes from `POST /v1/views/{id}/queries`** (Notion applies filter/sorts/`quick_filters` server-side — linked views often have `filter: null` with real chips in `quick_filters`), then properties are hydrated from the data source and ordered to match. Linked embeds (`empty data_sources`) never fall back to listing the source’s unfiltered “All” view or dumping the full DB. Return `notionView` to seed Thinktable layout when `viewSettings` is empty. **Empty `data_sources`**: resolve `data_source_id` from the view first, then URL source id, then fuzzy title search; if still unresolved, hide the table body (title/Notion chrome only) instead of a red error. Search normalizes `data_source` → `database` for the picker/import.
- After connect / **Import pages**: opens a Mindmap.so-style picker with Notion **tree** (nested pages), search, **Add frame** (Notion page or picked DB → title-variant `boardLink` frame like local board blocks + nested Thinktable board whose board-body holds the Notion content / `databaseBlock`; `notionPageId` / `notionUrl` for sync; same open menu as local boards + Notion icon right of open), and **Generate mindmap** (walks `child_page` + `child_database`; parent→child **threads**; Notion **pages** → title-variant `boardLink` frames + nested Thinktable boards in the Boards menu with Preview/Open/Notion open-menu; Notion **databases** → one map `databaseBlock` frame that live-loads a Notion-like **structured table** via `/api/notion/database/[id]` (columns = properties, rows = pages) plus a nested menu board — never one map frame per row; resolves `block_id` parents). **Add frame** on a nested DB inside a page body stays a compact `databaseBlock` (same table NodeView). Also creates nested Thinktable boards in the nav (linked via `linkedBoardId` / `sourceBlockMessageId`). **Sub-pages:** Notion `child_page` blocks become TipTap `boardLink`s in the parent board body; each sub-page gets its own Thinktable board with only that page’s content (discovered recursively on import even in card mode). Nested Notion **databases** inside a page body stay as TipTap `databaseBlock` atoms (table icon + title + Notion icon). Legacy sole-`databaseBlock` map frames migrate to `boardLink` on load via `ensureNotionMapFrameIsBoardLink` / `migrateSoleDatabaseBlockToBoardLink` (`lib/notion/migrate-frame.ts`) — including frames that never got `linkedBoardId`. DB table cells are **editable** (title/text/number/checkbox/select/multi_select/status/url/email/phone/date) via `PATCH /api/notion/page/[id]` → Notion page properties; select menus list **all schema options** from the DB property (not only current cell values). DB **view settings** (Thinktable-owned, on `databaseBlock` `viewSettings` JSON): drag property order + hide/show, search, filters, multi-sort, group-by, conditional row colors, sub-tasks (relation nesting), layouts (**table / board / list / gallery / calendar** live; timeline/chart/feed/map stubs) + layout toggles — UI `database-view-settings.tsx`, transforms `lib/notion/database-view.ts`. DB **rows** (Notion pages) show a left ⋮⋮ handle (open/delete) + top/bottom add hairlines on the **row border** (1px `#e5e7eb`, darkens on insert hover; CSS `group-hover/gutter`; no extra `tr` border — td rules only so alignment matches) (`POST /api/notion/database/[id]` create, `DELETE /api/notion/page/[id]` archive). Table chrome: no outer perimeter — TipTap `.prose table th/td` full-cell borders are wiped for `.tt-notion-db` in `globals.css`; only internal row rules + optional vertical dividers (`showVerticalLines`) remain.

## MCP (next phase)

- Per-user API keys / OAuth for MCP clients.
- Tools: list maps, create/link nodes, import Notion page, update page content, set layout.
- MCP writes go through Thinktable APIs; Notion writes use the stored connection when the node is Notion-linked.

## Non-goals (for this slice)

- Full Notion editor parity on day one.
- Replacing local notes with Notion-only.
- Marketplace listing / Notion security review (later for public distribution).

### Device testing (iPad)

Same Wi‑Fi (most reliable): `http://<mac-lan-ip>:3031` (e.g. `ipconfig getifaddr en0`). Quick tunnel: `cloudflared tunnel --url http://localhost:3031` → `*.trycloudflare.com` (DNS often fails on iPad Safari; prefer LAN). Auth/OAuth may still expect `localhost` / `NEXT_PUBLIC_SITE_URL`.

### Notion Developer portal setup (one-time)

1. Open [Notion Developer connections](https://www.notion.so/developers/connections) → create **Public connection**.
2. Capabilities: Read content, Update content, Insert content; user info as needed.
3. Redirect URI: `http://localhost:3031/api/notion/callback` (add prod URL later).
4. Copy OAuth client id + secret into `.env.local` as `NOTION_CLIENT_ID` / `NOTION_CLIENT_SECRET`.
5. Restart `npm run dev`. Top bar **Notion** button starts the hosted OAuth UI (workspace → permissions → select pages).

## Naming

Official terms live in **`DEFINITIONS.md`**. Short form:

| Official | Meaning | Code today |
|---|---|---|
| **Board** | The canvas (`/board/{id}`) | `conversations` |
| **Frame** | Box holding text (one or more **blocks**) | RF `chatPanel`, `metadata.isBlock` |
| **Block** | TipTap line + ⋮⋮ (not the box) | `EditorBlockRef`, `tiptap-block-handles` |
| **Thread** | Line between frames | RF `Edge`, `panel_edges` |
| **Connection point** | Knob that starts/receives a thread | RF `Handle` |

No “block group” type — multiple blocks in a frame is still a frame. RF `blockGroup` is legacy wrapper chrome. `metadata.isBlock` means **frame**, not TipTap block. Select **frame** before caret; ⋮⋮ drag = **block** only when armed via ⋮⋮ click, else **frame**. Frame **select** is click-release only (RF mousedown select blocked); mid-press hides selection chrome except on resize/⋮⋮/rotate chrome (`pressing` must not unmount `NodeResizeControl`). **move** shows a transient blue box only and never leaves the frame selected.

The **page icon/emoji and the open-menu pill are screen-relative** (same comfort curve as the ⋮⋮ grips: `chromeScale = 1/max(1,√scale)`). **Scale must be rotation-safe**: `elementUniformScale` walks ancestor CSS matrices and uses `hypot(a,b)` — never `getBoundingClientRect().width / offsetWidth` (AABB inflates under frame `rotate` and threw the icon off). Placement uses **Range glyph bounds → `screenToLocal`** for `iconShiftY`/`menuTop` (line-box `lh/2` sat below glyphs with 1.7 line-height and left the icon high when unrotated) and **`localToScreen`→`screenToLocal`** to clamp the open menu to the clip/panel right edge (gutter guess let the pill escape when rotated). Counter-scale is **transform-only** on the icon + absolute menu (`translateY(-50%) scale(chromeScale)`, `origin left center`) — never `marginRight`/width compensation that shrinks the boardLink flow box (that fed locked hug → `setResizeDimensions` → `setNodes` = `nodes(ref)` storm / max update depth / client crash). Hug width for boardLink uses icon **`offsetWidth`** (layout), never icon `getBoundingClientRect` (includes chromeScale). BoardLink rows use `align-items:flex-start`; the **icon** nudges with `iconShiftY` so its center matches the first-line Y. The ⋮⋮ grip for boardLink measures `.tt-board-link-label` (not the NodeView root — Range there hit the icon box mid-block). Icon + menu + grip share that first-line center. The **title text still scales as content** (only the icon/menu are counter-scaled). boardLink is **shrink-wrapped** (`width:max-content`) so menu `left` prefers just right of the title; if that would spill past the frame it slides left and **overlaps title text only** (never past the emoji/icon). The spill clamp reads the frame's own `.overflow-hidden` **only if `panel.contains` it**, else the panel — an unscoped `closest('.overflow-hidden')` matched the canvas-wide React Flow pane on **locked** frames (no inner clip), so the menu escaped the right edge. Frame min width is ⋮⋮ gutter + icon + open-menu pill. Title boardLink menus also reveal when hovering anywhere on the host frame (so body/regular blocks in a page frame still expose preview/open).
